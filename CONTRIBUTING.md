# Contributing

Contributions should improve clarity, provenance, testability, or usability without adding doctrine by implication.

## Before proposing a change

- Identify whether it is documentation, an implementation choice, or a substantive framework change.
- Preserve the separation of relevance, candidate generation, qualification, and authority.
- Keep Mythic material quarantined from factual and consequential authority.
- Add or update a synthetic scenario test when a change touches an invariant.
- Do not add dependencies, agents, databases, or user interfaces without a demonstrated need.

## Versioning

Do not edit `versions/v1.0/SKILL.md`. Substantive framework changes require a later version and a CHANGELOG entry. Clarifications must state whether they change interpretation or only presentation.

## Review standard

A proposed change should state its scope, evidence boundary, assumptions, possible falsifiers, and any effect on authority or final status. Prefer small, comprehensible commits.

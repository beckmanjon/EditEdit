# PAUL vs LSD — Unified Reasoning Protocol

## Purpose
This skill creates a single, coherent reasoning engine that synthesizes three complementary systems:

- **Beckman v3.1 (PAUL Application Layer)**: Disciplined operational structure using Listen → Search → Decide → Dream, four core strands (Grounded, Structural, Strategic, Adversarial), Low/Medium/High passes, KDP final gate, and strictly quarantined Mythic Wild Card.
- **LSD Fractal Reasoning**: Expansive multi-perspective divergence across six interpretive strands processed at Low, Medium, and High temperatures, with amalgamation, explicit Kill List, and rigorous base context sovereignty.
- **Real PAUL Framework Loop Discipline** (Plan-Apply-Unify): Mandatory closure, acceptance criteria defined upfront (Given/When/Then), Execute/Qualify loop inside execution, escalation statuses (DONE / DONE_WITH_CONCERNS / NEEDS_CONTEXT / BLOCKED), diagnostic failure routing, and strong anti-drift / anti-rationalization mechanisms.

**PAULvsLSD** lets you run pure Beckman v3.1, pure LSD, or (most powerfully) integrated hybrid modes that combine disciplined operational skeleton + fractal depth + mandatory Plan-Apply-Unify loop integrity.

The goal is maximum robustness, insight, and corrigibility with minimum narrative contamination, context drift, or false completion.

## Core Design Principles
- **Loop Integrity (from real PAUL)**: Every unit of work should have a clear Plan → Apply → Unify cycle. Mandatory closure with reconciliation, decision logging, and explicit comparison of planned vs actual. No orphan reasoning.
- **Recognition creates obligation**: Engage symbolic/meaning depth when present, but never let it govern.
- **Base context remains sovereign** at all times.
- **Acceptance Criteria first**: Define "done" (Given/When/Then) during planning/locking before execution begins.
- **Mythic / Symbolic output must be quarantined and labeled** (Symbolic Insight / Bias Warning / Poetic Color).
- **Explicit Kill List** for anything generated but discarded, with justification.
- **Execute/Qualify discipline**: After execution or synthesis, independently qualify against spec and acceptance criteria before moving on.
- **Escalation statuses**: Use DONE, DONE_WITH_CONCERNS, NEEDS_CONTEXT, BLOCKED to surface nuance honestly instead of binary pass/fail.
- **Diagnostic Failure Routing**: When issues arise, classify root cause (Intent issue / Spec issue / Evidence gap / Structural blocker) before patching.
- **High auditability**: Every output traceable to question type, strands, temperatures, and decisions.
- **Asymmetric optionality**: Lighter or heavier versions depending on stakes and ambiguity.
- **Tragic stewardship**: Disciplined core first; expansive depth only where it adds verifiable value.

## Three Operating Modes

### 1. PAUL Mode (Beckman v3.1 Strict)
Use when you need clear operational discipline, question locking, and traceable decision output.

**Process**:
- Explicitly lock the real question type first (Thesis-expression, Decision, Risk-control, Identity/meaning, etc.).
- Run Listen → Search → Decide → Dream structure.
- Use the four core strands only: Grounded/Empirical, Structural, Strategic, Adversarial.
- Low Pass (exploration + detection) → Medium Synthesis (core strands only) → High Pass (pressure testing) → KDP (final gate with action, invalidation, watch items).
- Mythic Wild Card activates only on strong triggers or explicit request, runs only in Low + High, and must be labeled Symbolic Insight / Bias Warning / Poetic Color. Poetic Color is excluded from decision logic.

**Best for**: Trading decisions, capital allocation, position management, house-hack analysis, career moves, any situation where "what should I actually do?" is the core need.

### 2. LSD Mode (Full Fractal Divergence)
Use when the goal is maximum perspective diversity and blind-spot detection on complex, ambiguous, or meaning-rich topics.

**Process**:
- Preserve base context exactly.
- Split into the six interpretive strands:
  1. Literal
  2. Structural
  3. Emotional / Psychological
  4. Strategic
  5. Symbolic / Mythic
  6. Adversarial / Critique
- Process each strand at Low, Medium, and High temperatures (18 perspectives total).
- Amalgamate strongest insights.
- Produce explicit Kill List with justifications.
- Run base context sovereignty check.
- Deliver structured output with Fractal Process Evaluation.

**Best for**: Worldview work, legacy/philosophical questions, complex systems analysis, creative or identity-laden topics, situations where linear reasoning feels insufficient.

### 3. Hybrid PAUL+LSD Mode (Recommended Default for Most Serious Work)
This is the integrated mode that combines the strengths of Beckman v3.1, LSD Fractal, and real PAUL loop discipline.

**PAUL Loop Overlay (Plan → Apply → Unify)**:
The work is structured as a mandatory cycle:

- **PLAN** (Enhanced Question Locking + Acceptance Criteria)
  - Explicitly lock the real question type.
  - State the sovereign decision sentence.
  - Define clear Acceptance Criteria upfront in Given/When/Then format.
  - Identify boundaries (what is out of scope) and coherence constraints.
  - Decide which strands and temperatures are needed (light vs full fractal).

- **APPLY** (Execution with Execute/Qualify + Fractal Depth)
  - Run the Low → Medium → High passes with selective LSD fractal expansion on Symbolic/Mythic and Adversarial strands.
  - After synthesis or key outputs, perform an independent Qualify step against the locked question and Acceptance Criteria.
  - Use escalation statuses: DONE / DONE_WITH_CONCERNS / NEEDS_CONTEXT / BLOCKED.
  - Apply Mythic quarantine and labeling on any symbolic output.
  - Surface diagnostic routing if issues appear (Intent / Spec / Evidence / Structural blocker).

- **UNIFY** (Mandatory Closure & Reconciliation — Never Skip)
  - Compare planned vs actual (what was intended vs what emerged).
  - Produce explicit Kill List with justifications.
  - Log key decisions and deferred issues.
  - Reconcile against base context and Acceptance Criteria.
  - Update any persistent state or handoff notes for future sessions.
  - Deliver final integrated output with clear action, invalidation criteria, and watch items.

**Fractal Expansion (LSD) Applied Selectively**:
- Heavier on Symbolic/Mythic and Adversarial/Critique (especially in High Pass and Unify).
- Lighter/conservative on Grounded/Empirical strands to protect evidence.
- All high-temperature output still passes through quarantine + Kill List.

**Result**: You get Beckman v3.1 operational clarity + LSD fractal depth + real PAUL loop integrity (mandatory closure, acceptance criteria, qualify discipline, and anti-drift mechanisms). This is the strongest configuration for high-stakes personal systems work.

## Escalation Statuses (from real PAUL Framework)
Use these to surface nuance honestly instead of binary pass/fail:

- **DONE** — Completed cleanly, meets Acceptance Criteria with no significant concerns.
- **DONE_WITH_CONCERNS** — Completed, but flagged doubts, risks, or edge cases for later review (especially useful in trading theses or long-horizon decisions).
- **NEEDS_CONTEXT** — Cannot complete properly — missing information, evidence, or clarity on the locked question.
- **BLOCKED** — Structural or external impediment (e.g., missing data source, capital constraint, emotional state, external dependency).

In Hybrid mode, apply these statuses to key outputs, strand contributions, or the overall synthesis before Unify. This prevents silent false completion and feeds directly into diagnostic routing and the Kill List.

## Question Locking (Highest Leverage Step — From PAUL)
Before any strand work, explicitly identify:

**What kind of question is this really?**

Common types:
- Thesis-expression ("What instrument best expresses this idea?")
- Decision ("What should I do?")
- Risk-control ("What can hurt me?")
- Timing ("Now or later?")
- Position-management ("Add, hold, trim, hedge, exit?")
- Identity/meaning ("Why does this matter to me?")
- Interpretive / Research

State the locked question clearly. This is the sovereignty lock. Poor question locking is the most common failure mode (e.g., treating a thesis-expression question as pure valuation).

## Mythic / Symbolic Handling (Unified Rule)
Whether in PAUL, LSD, or Hybrid mode:
- Mythic/Symbolic output is **never** allowed to drive decisions.
- It must be labeled as **Symbolic Insight**, **Bias Warning**, or **Poetic Color**.
- Only Symbolic Insight and Bias Warning may influence KDP or final synthesis.
- Poetic Color is killed or footnoted.
- High-temperature Symbolic work is especially valuable in High Pass for revealing hidden structure or self-deception, but still quarantined.

## Output Structure (Hybrid Mode Recommended)
1. **Question Lock & Sovereign Decision Sentence**
2. **Mode Declaration** (PAUL / LSD / Hybrid + any modifiers)
3. **Key Strand Insights** (summarized, noting temperature/fractal contributions where relevant)
4. **Mythic / Symbolic Contributions** (explicitly labeled + quarantined)
5. **Kill List** (explicit discards with justification — from LSD discipline)
6. **KDP / Final Decision Gate**
   - Action now / Preferred path
   - Invalidation criteria
   - What would change the answer
   - What must be watched next
   - Vehicle / Capital efficiency notes (when relevant)
7. **Fractal Process Evaluation** (added value vs. risks/distortions)
8. **Base Context Fidelity Check**

## Guardrails (Strict — Inherited from Both Systems)
- Base context sovereignty is non-negotiable.
- High-temperature speculation must be flagged or killed if it drifts from the locked question.
- Narrative capture checks are mandatory on conviction-heavy topics (trading, ideology, identity).
- Poetic or resonant output that does not clarify meaning or expose distortion is excluded from decision logic.
- The protocol is only as good as the question it locks. If the locked question feels wrong mid-process, surface it and re-lock.

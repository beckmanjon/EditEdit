# PAUL vs LSD

## Purpose

Use PAUL vs LSD to produce bounded, auditable reasoning and execution without exposing private reasoning traces. Preserve the control loop:

```text
Plan → Apply → Qualify → Authority Gate → Unify
```

Use LSD for controlled divergence only. Route the Beckman application layer through Listen → Search → Decide → Dream.

## Operating rules

1. State the question, scope, base context, evidence boundary, and acceptance criteria.
2. Generate candidates without treating recognition, relevance, attention, confidence, symbolic resonance, or agreement as authority.
3. Qualify candidates with evidence, assumptions, limitations, and explicit falsifiers.
4. Quarantine Mythic material: it may illuminate questions and alternatives, but cannot independently establish facts, raise empirical confidence, resolve factual disagreement, determine responsibility, or authorize consequential action.
5. Apply the Authority Gate. Return one of: Hypothesis, Working conclusion, Qualified recommendation, Authorized decision, or Rejected / quarantined.
6. Unify only surviving candidates. Rejected candidates do not silently return.
7. Produce a bounded output and decision record. Give receipts, not hidden chain-of-thought.

## Complexity budget

Shrink the protocol for routine, reversible work. Expand it when stakes, ambiguity, novelty, disagreement, irreversibility, or evidence conflict justify added ceremony. Escalation, `NEEDS_CONTEXT`, `BLOCKED`, and `QUARANTINED` are valid outcomes.

## Final statuses

Use `DONE`, `DONE_WITH_CONCERNS`, `NEEDS_CONTEXT`, `BLOCKED`, or `QUARANTINED`. Procedural closure is not epistemic closure: state remaining uncertainty and what would change the answer.
